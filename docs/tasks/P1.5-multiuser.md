# P1.5 · Multi-user accounts (before P2)

Replaces the single `CLIPFLOW_API_KEY` login with real users. One commit per part, report after each
(≤ 10 lines). Requested 2026-10-05.

## Spec
- **Users:** `users` table (username, argon2 password hash, role `admin|member`, active, created_at).
  Sessions stored in the DB; HttpOnly + SameSite=Lax cookie; login rate-limit; logout; change password.
  Admin page to create/disable users and reset passwords. **No public signup.**
- **First run:** create the admin from env `CLIPFLOW_ADMIN_USER` / `CLIPFLOW_ADMIN_PASSWORD` (read once) and
  assign ALL existing rows to it.
- **Ownership:** `user_id` on jobs (candidates via their job), watermark_assets, campaigns, and every new table
  from now on. Per-user settings table for user-level keys (subtitle defaults, active watermark, caption
  defaults); global settings stay admin-only (AI keys, Whisper, disk).
- **Scoping:** every endpoint filters by `current_user`; other users' rows return 404. File endpoints (video,
  thumbnails, watermarks) check ownership via the session cookie. `/api/activity` shows only the user's own
  tasks (admin sees all).
- **Worker:** reads settings for the job's owner (user setting → global → default).
- **API tokens:** per-user API tokens (hashed) for scripts, replacing `CLIPFLOW_API_KEY`; keep
  `CLIPFLOW_API_KEY` working as an admin token until the user confirms its removal.
- **UI:** login page in the mockup's visual style; island and stepper unchanged.
- **Docs:** document in CLAUDE.md, including the ownership invariant: every query is scoped by `user_id`.

## Process
One commit per part, `docs/changes/` entry each, verified on the running stack; report after each part.
